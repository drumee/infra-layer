# P1 bounded HTTP transport instrumentation

Test-only opt-in CommonJS modules in test/diagnostics/postfix-http. Gate D design: static inspection complete; Gate E must qualify behavior before any real Services diagnostic. No canonical Services, dependency, production, Docker configuration, assertion, timeout, readiness or retry edits.

observe.cjs logs attempt UUID, process incarnation UUID, PID, role, per-process sequence, hrtime and UTC. Socket/request IDs correlate within a process; endpoint/project/container and daemon events correlate lifecycle. Docker NAT may prevent direct tuple equality across host/container. UTC is contextual; no millisecond cross-process causal inference. Controlled fixtures share an append-only private file and explicit startup/IPC handshakes; process-exit callback receipt can lag actual exit. Daemon event timestamps are a separate clock/domain.

Client observes fetch start/signal/error cause chain; Undici request creation/send socket/connect/header/body-trailers/error; socket end/close/errorMonitor and public tuple/byte counters. Fetch delegates exactly once and rethrows the original object/cause. No body interception or pooling policy change. Channels documented for Undici6.23.0 are experimental supplementary evidence; public server/socket/process events and actual assertions independently support interpretation. Response body completion is parser completion, not application JSON acceptance; canonical count trace supplies the latter. Client deadlines not exposed by those APIs are explicitly unavailable.

Server preload wraps the one synchronous actual capture handler, preserving this/arguments/return/error; records enter/return/throw and headersSent/writableEnded/writableFinished flags. Response finish/close distinguish completed and interrupted output. Server listening logs actual address and timeout settings. Socket connection/end/close/errorMonitor, server close request/completion, process start/uncaughtExceptionMonitor/exit and passive SIGTERM emit observation preserve default fatal exception/signal handling. No normal error handler is added to mask failure. This instrument is scoped to the known synchronous capture handler; it makes no claim of generic asynchronous-handler rejection coverage.

Real wrapper loads the fixed canonical runner and changes only the exact test-child selection to the three original cases plus a preload. For the mission-owned capture build only, it copies diagnostic modules/config and changes copied Dockerfile entrypoint to node --require server-preload.cjs /fixture/capture.js. Actual capture.js bytes stay exact. No arbitrary source evaluation/path module loader. Canonical runner retains all Docker commands and assertions; wrapper adds owner-filtered read-only inspections/events, and diagnostic copied-build operations only. The capture observer writes /capture/.p1-http.jsonl (not .eml), preserved across deliberate capture restart, copied before fixture deletion after cleanup. Canonical file filtering ignores it. No secret mount or network is added.

4096-event hard limit per logger makes overflow fatal; process instances and bounded run duration bound combined files. Files use0600 and output directories0700; capture file inherits the existing private capture directory. The canonical runner's own temporary root remains0755 for its existing service setup; secret/capture subdirectories retain0700. Output allowlist excludes request headers, response headers, payloads, arbitrary error messages/stacks and credentials. Errors include bounded name/code/cause/socket metadata only. Controlled secret sentinel is sent but must never appear in diagnostics. Logging failures remain fatal. SIGKILL cannot emit a child process.exit; parent/daemon observation is required in that case.

Instrumentation necessarily adds synchronous event writes and a fetch Promise continuation, so it can perturb timing. It preserves functional behavior, response body, exceptions and existing deadlines; a successful instrumented run cannot exclude a timing-sensitive historical failure. Modules are injected only into owned diagnostic processes; nothing is persisted globally.

API references: [Undici6.23.0 channel contract](https://raw.githubusercontent.com/nodejs/undici/v6.23.0/docs/docs/api/DiagnosticsChannel.md), [Node22.22 HTTP events](https://nodejs.org/download/release/v22.22.0/docs/api/http.html), [errorMonitor semantics](https://nodejs.org/docs/latest-v22.x/api/events.html#eventserrormonitor). Public events supplement the experimental channel contract; no undocumented runtime internals are the sole evidence source.
