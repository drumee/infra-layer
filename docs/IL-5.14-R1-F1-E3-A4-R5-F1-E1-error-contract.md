# Recovery admission error contract

Caller authorization is first. Missing context, authorized!==true, missing verified prior/pending recovery-required operation, or missing/undeclared journal failed-service scope refuses ROLLBACK_OPERATION_NOT_AUTHORIZED before candidate/runtime identity details or network admission. Public rollback must apply this caller check before reading active.json.

For an authorized, scoped operation, verify immutable candidates and every inventoried resource identity before deciding whether the exact failed-service/failed-revision target is present and eligible. Unknown runtime revision/service/name/project/owner/image is RUNTIME_IDENTITY_MISMATCH where established by checkObserved. Duplicate services retain DUPLICATE_SERVICE_IDENTITY. Source preparation/compatibility failures keep their specialized errors. Only after these checks may absence of the scoped failed target refuse eligibility/admission; it does not relabel an already established identity defect.

The saved historical test is Case A: authorized:true, valid prior, recovery-required revision, declared journal service application; it changes only one runtime identity field. Its original RUNTIME_IDENTITY_MISMATCH expectation is correct. The earlier new R5 E11 test likewise has authorized caller/valid scope and an undeclared runtime service. Its ROLLBACK_OPERATION_NOT_AUTHORIZED expectation encoded the regression. Correcting that newer expectation to RUNTIME_IDENTITY_MISMATCH follows the same independently established contract; it does not authorize changing the historical assertion or treating refusal as success.

The helper currently combines trusted journal scope with runtime service/revision presence at line8. Split these predicates, retaining trusted-scope authorization first and moving only runtime-presence eligibility after the identity loop. No catch/relabel, network change or general bypass. Correct degraded endpoint admission remains separate from readiness. Extra/missing/wrong-ID/endpoint memberships and Docker errors remain fatal. Final strict networks, process health and protocols remain required.
