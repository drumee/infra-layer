No correction is proposed for a mere pattern risk. Response-finish is server output completion, not application receipt. P2 records transport body completion and subsequent JSON processing independently. SIGKILL cannot run a process exit handler; daemon/parent exit observation is required. A callback-based SMTP onData finishes disk write before successful callback; raw message bodies are never logged. Docker .State health/readiness after recreation may transiently be starting, which must not be relabeled healthy.

## Separately demonstrated diagnostic defect

VERIFIED_DEFECT: the new P2 Docker event collector shutdown classification rejects the actual Docker29.2 CLI completion code143/signal:null after an observed intentional SIGTERM request. It sets exitCode1, which the orchestrator retains. This is a diagnostic lifecycle defect, not an interruption of a capture HTTP request; it occurs after all17 native cases and owned Compose cleanup. The written mandatory-stop/G4 policy prevents further execution. It is explicitly outstanding; no speculative capture/Postfix correction is applied. A follow-up must qualify the observer's controlled termination contract, unexpected-exit controls and partial-output failure behavior before a separately justified campaign can be considered.
