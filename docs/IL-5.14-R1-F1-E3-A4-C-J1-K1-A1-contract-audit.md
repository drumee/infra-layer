# Network and recovery contract audit — Gate F PASS

Production source is unchanged. serviceNetworks checks declared roles; validateNetworks inspects exact declared network identities, attachment maps and complete project inventory. containerNetworks refuses full-set mismatch, missing/wrong NetworkID, unsupported empty endpoint or missing network-map attachment, then EndpointID/name mismatch. Ownership, malformed identity and Docker failures retain their distinct fatal errors. NETWORK_ATTACHMENT_UNSETTLED is reserved for supported synthetic ep- metadata after full membership/ID checks; only that code receives existing5s/50ms bounded reconciliation.

Public rollback requires authorized caller/revision/active state and compatible candidate. Private rollbackOperation selects exact journal/candidate authority. authorizeRollback verifies prepared images/resources/runtime identity and invokes authorizeRecoveryNetworks. It does not declare operational readiness. The only degraded endpoint exception applies to the exact approved target, running=true/restarting=true, empty endpoint, no conflicting attachment, with complete configured network set and NetworkID already validated. Actual recreation and final ordinary strict checks remain mandatory. Ordinary recover:true is not a bypass.

Error taxonomy is preserved: INVALID_NETWORK_ATTACHMENT for malformed network data; NETWORK_ATTACHMENT_MISMATCH for contract membership/identity/unsupported endpoint differences; RUNTIME_IDENTITY_MISMATCH for recovery target/candidate identity mismatch; ROLLBACK_OPERATION_NOT_AUTHORIZED for missing authority/journal/target admission. A final MISMATCH does not itself establish incorrect classification or a validator defect.

The R5 acceptance explicitly waits to observe restarting before exercising its degraded rollback target; the canonical application group does not add that observation wait. This is a discriminating difference, not yet a finding or authorization to add a delay. The diagnostic preserves canonical sequencing and logs exact actual reads and journal context without adding Docker probes between expected failure and rollback. No recovery or validator correction is selected.
