# Intended closed-manifest contract — Gate C PASS (definition only)

`SAFE_TO_REMOVE_OWNED_FIXTURE_VOLUME` requires one exact current-attempt manifest entry, successful corroborated creation receipt, canonical ordered creation times, a nonce bound to ownership labels and receipt, matching name/driver/scope/CreatedAt/labels/options/mountpoint fingerprint, and the authorized daemon ID/context/socket. The lifecycle must explicitly permit disposal. Labels or names alone never authorize removal; historical manifests cannot be adopted. Ambiguous entries, absent creation evidence, invalid timestamps, missing labels, different identity/context, unknown retention and failed inspections refuse.

All container references count: created, running and stopped. `ps -a` plus actual Mounts inspection must establish exact Name references. An owned remaining consumer is also in use; ownership does not make a live reference disposable. The intended mechanism re-observes daemon, identity and references immediately before exact non-force `volume rm`. Docker's in-use refusal is the final defence against a consumer appearing after observation. No force deletion or foreign-container removal compensates for races. A missing resource is not successful cleanup unless an exact prior verified removal receipt exists; an absent volume with a contradictory consumer snapshot refuses.

Retained evidence receives a preserve disposition. Successful removal requires a fresh absent/readback and zero references. Duplicate cleanup cannot broaden the manifest. Original qualification errors and cleanup errors are separate, persistent outcomes. Partial required cleanup is INCOMPLETE. Global pre/post volume/container/network metadata equality is intended as an additional accounting guard, not a substitute for exact ownership.

Docker volumes have no immutable object UUID equivalent to container IDs. Name plus metadata/nonce and trusted creation evidence is a scoped test boundary, **not** defence against a privileged Docker administrator deliberately reproducing identical metadata. Inspection errors remain fatal. No content mount of unknown resources is permitted. The new implementation is a standalone unqualified test draft; legacy fixtures have not adopted it. A defined contract is not real-Docker qualification.
