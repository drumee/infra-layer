# Recovery preflight boundary design

Gate C design: select separate admission from private authorized rollback operation and verified recovery-required journal evidence, never from an earlier volatile Restarting snapshot. The failure record must name one failed service; only its exact failed-candidate container may receive the empty-endpoint accommodation. Other containers still receive complete strict membership/endpoint validation. No generic mismatch catch or retry.

Verify immutable rollback target, active and failed candidates, compatible revisions, project/instance, exact canonical name/service/container ID, image/image ID/revision/role/mounts and configured HostConfig.PortBindings. An empty live NetworkSettings.Ports is not evidence of wrong configured exposure during backoff; configured bindings remain exact and any observed live binding must be declared. Recheck stable identities and configured bindings/mounts at network authorization. Running/Restarting are volatile observations, not immutable identities: evaluate the narrow endpoint condition at that actual inspection, with boolean schema checks. Unexpected networks, IDs, endpoint conflicts and Docker errors remain fatal. Do not authorize incomplete endpoints for unrelated services.

The helper returns only admission evidence. Existing service recreation, strict final network check, health/protocol checks and final inspection remain mandatory. Normal activateDeployment, recover:true resume, backup resume, restore and rotation do not acquire the private rollback operation. The internal activateRollback wrapper must independently enforce compatible rollback/active evidence under lock because its module is accessible through the existing lifecycle wildcard export. No public bypass flag is added.

Audit the admitted service/container via bounded existing activation-intent details and record the failing service in new activation-failed/recovery-required events (journal already supports service). Historical entries are unchanged; missing service evidence does not gain the new permission. Normal healthy rollback continues through strict admission when no recovery-required event exists.
