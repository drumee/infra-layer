# IL-5.14-C1-D1 diagnostic contract

Gate B: PASS for the defined contract;controlled execution results are recorded separately. The actual path is test/support/qualification-diagnostic.cjs,used by the real network script and isolated process fixtures. It changes evidence,not assertions or execution outcomes.

The first failure writes exclusive mode0600 failure.json in an absolute,real,owned mode0700 directory. A structured record includes timestamp,scenario,step,sourceRevision,execution UID/GID/cwd/Node,assertion location,Error name/code/message/operator/actual/expected/stack/cause and available command/output/exit details. Absent fields are omitted. Non-enumerable properties and the native Node stack accessor are read explicitly. Untrusted getters are not executed. Nested causes,circular references,BigInt,Symbol,Map,Set,Buffer,undefined and non-finite numbers have safe representations. Buffer contents and arbitrary environments/configuration are omitted.

The original process still fails with status1. The first exception is captured before finally cleanup;the same exception is rethrown. Cleanup remains mandatory and independently traced. If cleanup replaces the outward exception,the original artifact remains immutable and the secondary failure is traced. Artifact-write failure is explicitly reported with the original nonzero outcome. No failed operation receives a success record and no retry is added.

The command observer delegates the exact original execFileSync receiver,arguments/options,input,timeout and return value or exception. It runs only after the unchanged trusted tool selection and adds no Docker operation. It retains bounded,expurgated stdout/stderr and safe inspection metadata already returned by the original commands. Container inspection uses a whitelist for identity,state,ownership and network relationships;Config.Env,Docker credentials and health-command logs are not dumped. Shell/program/environment payload arguments are omitted. Spawn-based start behavior is unchanged;its existing result/command assertions remain available in the diagnostic context.

Generated credentials are registered before use and removed wherever they appear. Sensitive named fields,assignment values,Bearer tokens,URL authentication and private-key blocks are redacted. Public error codes,container/endpoint IDs and source locations remain useful. No process environment or Docker configuration dump is produced.

Each JSON record is bounded to32768 bytes including its final newline. Strings,depth,nodes,arrays and object fields have limits and explicit omission/truncation markers. The trace has at most512 records (at most16MiB),with saturation disclosed in the failure report;the latest bounded command context is retained independently. A concise human summary identifies scenario,step,code,message,assertion source and artifact path. Passing execution creates no failure artifact and retains its original success output.

The required regression cases exercise the same failed child-process reporting path,including actual Node AssertionError and a genuine trusted Docker failure against a unique nonexistent qualification identity. No real service is disrupted to manufacture a failure. Correct diagnostics are a prerequisite for the single instrumented real reproduction;they are not a functional fix.
