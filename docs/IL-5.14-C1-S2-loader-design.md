# IL-5.14-C1-S2 secure loader design

Gate B: PASS for the design before implementation. No arbitrary source evaluation, eval/Function/VM equivalent, scanner exclusion or public API expansion is selected.

Current implementation tests will use a fixed literal CommonJS require of lifecycle/docker. Node's supported mock.method temporarily substitutes only child_process.execFileSync while the fresh module captures that dependency. The builtin and its previous cache entry are restored synchronously in finally. Each returned instance retains its own fixture executor; other callers retain their original module and executables. No filename/source/CLI argument is accepted. Invalid executor types or extra arguments fail before any substitution. This is trusted repository code with restricted test substitution, not a claimed sandbox for untrusted code.

Historical alpha.3 will not be executed. A fixed git-show commit/path is read, its complete SHA256 and the realistic metadata fixture SHA256 are checked, and AST inspection verifies the original unconditional Object.keys attachment loop and direct id-to-inspect array. The historical command vector is derived as data, then passed through the actual current Docker adapter with the controlled failing executor. This preserves the old invalid-object/failed-command negative proof and the current corrected tests, without interpreting historical JavaScript. The earlier executed-source reproduction remains immutable evidence. Unapproved identities/bytes/CLI arguments are rejected; there is no general AST interpreter or executable-source option.

To remove the second VM export injection, the existing bounded readiness algorithm moves into a small private internal module. An internal factory accepts a monotonic clock and async delay for deterministic tests; production uses the same performance.now,5s deadline and50ms delay as before. Only successful unsettled metadata is re-observed; Docker/ownership/missing-object errors escape immediately. Public root/lifecycle exports and declarations are unchanged. This legitimate production helper adds one package member, requiring package audit and complete runtime requalification; no privileged test loader is packaged.

The13 network tests retain every identity,ownership,absence,nonzero,stale-resource and bounded-readiness assertion. Additional tests cover fixed current-module loading, invalid source arguments, historical hash/metadata rejection, builtin/cache restoration, no unexpected host operation and negative child exit.

Promise ownership is corrected separately: diagnostic.run finishes task/cleanup evidence, rejects the original failure, and each entry point uses an explicit .catch(diagnostic.fail). The terminal handler records one bounded/redacted summary and nonzero exit, never an empty catch or void-only discard. Original task failures remain primary if cleanup/reporting also fails. Actual child-process regressions cover assertion, async/Docker failure, cleanup failure, evidence-write failure and no false PASS.

[Node22 mock.method documentation](https://nodejs.org/download/release/v22.22.0/docs/api/test.html#mockmethodobject-methodname-implementation-options), [CommonJS cache behavior](https://nodejs.org/download/release/v22.22.0/docs/api/modules.html#requirecache). No new dependency or experimental module-mock flag is required.
