# V1-F2 comparator contract — Gate B BLOCKED (execution qualification)

Only container mount membership within an inventory is unordered. Container, volume and network lists retain their existing ordered identity checks; no global sorting or filtering is performed.

Current normalized fields are type, volume name, destination, source_hash (SHA256 of JSON string Source using the existing digest), volume driver, rw boolean, mode and propagation strings. Names/drivers are null for non-volume mounts because Docker does not define volume ownership there; source must still exist as a string, nonempty for bind/volume. No path, access, mode or propagation equivalence is introduced. Exact string differences remain differences. Host Source paths stay private; a collision-resistant source digest preserves identity without exposing unrelated paths. Read-only fixture expectation uses the freshly verified owned volume mountpoint hash, exact volume name, destination /fixture, local driver, rw=false, empty Mode and Propagation for --mount volume semantics.

Each validated complete tuple is serialized in a fixed field order, counted in a Map, and compared by multiplicity. A Set is used only to enumerate all keys from both count maps; no record occurrences are discarded. Equal cardinality alone is insufficient. Missing/extra/modified/duplicate mounts throw MOUNT_MULTISET_MISMATCH. Invalid collection, sparse/null entry, unknown/missing field, invalid identity/path/access type throws INVALID_MOUNT_EVIDENCE even on both sides. Empty collections are allowed for inventory containers without mounts. projectMount checks actual Docker evidence before projection. Unknown raw Docker fields are outside this explicit contract, not globally normalized.

Raw projected array order is preserved in before/after and owned mount observations. Source arrays and records are never mutated. Inventory comparison first checks every other projected field, then mount multisets at the same verified container positions. Legacy three-field replay is a separately named function used only by deterministic regressions, never a fallback in the campaign.

Mismatch diagnostics are bounded to eight missing and eight additional identity hashes with full occurrence counts and total identities. A single differing pair reports changed field names; complex differences retain identity/count evidence without speculative pair attribution. No raw source/destination values appear in mismatch messages. The caller retains complete projected evidence. Exceptions propagate; primary/cleanup outcomes retain the unchanged ownership module policy.

The design is implemented but not qualified: the first regression command failed before per-case results. Static review does not close the finding.
