# D1 test architecture — Gate B PASS

F2 shell orchestration invokes Python run.py; it verifies frozen inputs and protected Docker configuration, then subprocess.run invokes node --test with the single explicit test file. The file is parsed/loaded as CommonJS. Top-level imports and three projectMount fixture constructions precede registration. Five tests are registered before historical snapshot reads; remaining calls and a ten-entry loop follow. Test callbacks are synchronous except intentional test-runner completion. No generic comparator wrapper catches and converts failure to success.

Installed Node22.22.0 source internal/test_runner/runner creates an isolated child via spawn(process.execPath,args), setting NODE_TEST_CONTEXT=child-v8. Child stdout carries framed V8 events, not ordinary text; stderr lines become test:stderr events. The parent waits for child exit and stdout completion. Nonzero child exit with no parsed failing subtest produces ERR_TEST_FAILURE('test failed',testCodeFailure), exitCode/signal and stackundefined. This exactly explains the summary format while leaving the child cause unknown. Node's reporter composition/bootstrap can itself throw. Native uncaught/rejection handlers classify asynchronous activity; a new rejection listener could change behavior and is avoided.

The F2 Python recorder waits for process completion, preserves the nonzero return code, and merges output. It has no Node exit/close listeners because it is a synchronous Python parent. It does not filter individual results out of the saved file; the original stream lacks those results. Its final tail presentation is not the saved evidence. A recorder error could have prevented later receipts, but actual complete ledger/STOP and matching log hash contradict a demonstrated file-copy loss. Source-only inspection does not exclude earlier Node reporter failure.

D1 retains the Node CLI/isolated-worker architecture and same target. Supported --require and --trace-uncaught add worker-side load/error journals; native multiple reporters add TAP plus event JSON. Python drains stdout and stderr separately through EOF before wait/receipt. Original child exit and collection state are separate; no failure is mapped to success. No test-name selection/isolation/dependency/version change.

Primary references: [Node22.22.0 execution model and reporters](https://nodejs.org/download/release/v22.22.0/docs/api/test.html#test-runner-execution-model), installed-source hashes/locations in independent-review/node-architecture.json. Native sources were inspected locally via process.binding('natives'), never used to execute comparator code. Original worker failure is an observed process outcome, not a root-cause taxonomy selection.
