# Complete network membership contract

Gate B PASS. Canonical composition services use array roles (gateway) or object roles with aliases (infrastructure services). Each role resolves through `compose.networks` to a unique Docker network name and a verified64-hex Docker ID. No implicit/default/external name resemblance authorizes connectivity. Public interfaces remain unchanged.

`require_existing` continues to require declared networks, not creation of every service. An absent service is valid during preparation and staged startup. Every existing project-labelled container is inventoried with `ps -a --no-trunc`, including created, stopped and entirely disconnected containers. Its project, owner, service, ID and canonical instance/run name must be validated; a label alone is insufficient. No unrelated container is modified. Members found on a declared network are also validated independently of the inventory, so foreign attachments cannot disappear from observation.

For each existing container, observed network names must equal the service's resolved declaration, including legitimate multihoming. Every NetworkID must match the inspected network; active EndpointID must match the reverse network attachment entry. Running containers require complete active attachments. Docker preserves configured membership with empty EndpointID for created/stopped containers; this is allowed only for a nonrunning container with no reverse active attachment and correct configured NetworkID. A stopped container with a missing configured connection is still rejected. No exception permits an extra network.

The established `NETWORK_ATTACHMENT_MISMATCH` code is used for extra, missing, wrong-ID, wrong-endpoint or ambiguous memberships; it is non-transient and is never polled by readiness. Malformed declarations/metadata are explicit `INVALID_NETWORK_ATTACHMENT`; ownership remains `NETWORK_OWNERSHIP_MISMATCH`; genuine Docker errors propagate unchanged.

Sandbox-less `ep-<EndpointID>` metadata remains a refusal: recognized expected names produce bounded `NETWORK_ATTACHMENT_UNSETTLED` only after all ordinary/inventory members pass. Unknown endpoints remain unauthorized. Such metadata never grants ownership or permits additional connectivity. Disconnecting an existing required connection is a negative state; reconnecting restores validity. Cleanup absence is accepted only after container removal, and network absence only when `require_existing:false` and no existing container requires it. No automatic repair/disconnect/delete or general retry is introduced.
